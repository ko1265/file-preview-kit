# Screenshot Checklist

Updated: 2026-05-09

Use this checklist for the final release visual check and any manual review needed for public release material.

## Demo Scene Order

1. Public URL sample
2. Auth-shaped request sample
3. Office sample
4. Media sample

## How To Switch Scenes

- Use the demo's sample select or sample cards to move between scenes.
- Keep the demo shell visible in the screenshot so the public story is obvious.
- Do not add new Office breadth while preparing the screenshot.

## Capture Goal

- Capture one compact screenshot that shows the demo shell, the curated sample list, and the browser-only preview story.
- Use [PUBLIC_DEMO_NOTE.md](PUBLIC_DEMO_NOTE.md) and [PUBLIC_LAUNCH_ASSETS.md](PUBLIC_LAUNCH_ASSETS.md) as the caption and framing source.

## Manual Fallback

- If the visual needs to be refreshed, review it manually from the demo page.
- Keep [LAUNCH_ASSET.svg](LAUNCH_ASSET.svg) as the release-facing visual reference.
- The Office scenes are backed by local static demo files, so they should be the primary publish screenshots.
- If the auth-shaped request scene is unstable, keep the example in the demo and capture it only when the manual path is reliable.

## Verification

- Confirm the launch asset or reviewed visual still matches the canonical caption.
- Confirm the public story does not imply layout-faithful Office rendering.
- Confirm the public story does not promise a stable third-party endpoint.
